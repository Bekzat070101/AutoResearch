# skills · 给模型的工作说明

本目录两类东西：可执行工具（`pku-course/`，有脚本和测试）和给模型读的工作说明（`SKILL.md`，由 `server/skills.py` 读进 system prompt）。

## 写成代码，还是写成 skill

| 这件事… | 放哪 | 例子 |
| --- | --- | --- |
| 有唯一正确答案，或错了会伤人（安全、隐私、编造） | 代码 | 压缩包解压限制、文件是否存在、链接是否来自检索结果、检索时间 |
| 要访问外部网站或接口 | 代码（adapter） | 开源之夏、北大开放数据、课程检索 |
| 结果要可复现、可测试 | 代码 | 阶段判定、候选打分、规则回退 |
| 需要读懂自然语言、做取舍、写评语 | skill | 候选里哪个最适合这个阶段、成果和项目要求对不对得上、下一步改哪里 |
| 规则会随课程、学期、网站改版而变，且非程序员也要能改 | skill | 各阶段优先看哪些来源、每个来源怎么搜、评语口吻 |

## 规矩

- 代码先跑，模型后判：代码把能确定的结果（上限、候选列表、可引用的原文）交给模型；模型只能在这个范围里选和写，不能新增项目、链接或证据。
- 代码必须校验模型输出：返回的 id 必须在候选里，引文必须真的出现在原文里，判定不能高于规则上限；不合格就丢弃，回退规则版。
- 没配模型时每条链路都能用规则跑通，界面上标出「规则版」。
- SKILL.md 只写会改变模型行为的内容：输入是什么、按什么顺序判断、输出什么格式、禁止什么。一条一行，不写背景介绍。
- 改 SKILL.md 不用重启服务（按修改时间重读）；改完在 CHANGELOG 登记。

## 现有

| skill | 读它的代码 | 做什么 |
| --- | --- | --- |
| `pku-course/` | `server/pku_adapter.py` | 北大教务公开课检索（可执行工具） |
| `project-scout/` | `server/projects.py` | 从检索到的候选里挑适合当前阶段的练手项目，写「在练什么 / 大概要做什么」 |
| `project-review/` | `server/submission.py` | 按五条标准评阅项目成果压缩包，写能指出下一步的评语 |
| `tutorial-distill/` | 离线：检索公开大纲/教材，蒸馏成 `knowledge/tutorials/{id}.json` | 主干 + 有据才分叉；每个节点带学什么/做什么/原链接；不够 2 个独立来源就标 insufficient，不编 |
| `paper-tutor/` | `server/tutor.py` | 按节出考察题：模型选题面和锚点句号，代码判对错；学生作答不发给模型 |
