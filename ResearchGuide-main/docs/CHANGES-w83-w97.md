# 修改总览：w83 → w97（2026-10-17 ～ 10-18）

> 本文对比本轮开发的**起点版本（w83，commit f4c91f6）**与**当前版本（w97）**的净差异，
> 只描述"改之前是什么样、改之后是什么样"，不记录中间反复调过的过程。
> 涉及 11 个改动文件（+791 / -170 行），新增 `server/tests/test_feedback.py` 与本文档。界面版本从 w83 升至 w97。

## 一、画像与方向系统重构（最大的一块）

**改之前（w83）**：方向是全局单选——右上角"方向"按钮点开切换当前方向；"我的方向"
存在全局 prefs 里；"我的"页有独立的"我的方向"卡片和一条画像切换栏（画像自动叫
画像一/二/N，切换即生效）；存在"当前方向"概念，方向树、对话推荐栏到处显示"当前"。

**改之后（w97）**：

### 1. 方向变成"每份画像内的多选"
- 每份画像的 trail 里新增 `dirs`（该画像添加过的方向，即菜单选项池）与
  `sel`（勾选中的方向，推荐按它来）两个字段，随画像存在服务端；老数据
  （全局 prefs 方向、只有 dir 的 trail）首次进入时自动迁移。
- 右上角"方向"下拉即多选控件：添加过的方向全部常驻列表，`✓` 表示勾选进推荐，
  点击即切换，**无任何 toast 弹窗**，勾选状态在菜单里直接可见。
- 新添加的方向默认勾选；允许全部取消（推荐回落到泛兴趣）；`sel` 缺失的老数据视为全选。
- 界面上不再出现"当前方向/（当前）/设为当前"字样（教程路径内部仍保留一条主线，
  由方向树"确认这个方向"决定，但不再作为"当前"露出）。

### 2. 画像管理与命名
- 画像支持**自定义命名**：`portraits` 表新增 `name` 列（自动迁移），
  新增 `POST /api/portraits/rename`。
- 默认命名规则：一个方向 = 方向名；多个方向 = 最先加入的两个用 `·` 连接
  （如 `心理学·经济学`）；都没有才叫 `画像N`。自己起的名字始终优先。
- "我的"页重做为"画像与方向"区块：**画像条在方向卡上方**（修复了旧版负 margin
  导致的重叠跑版），当前画像高亮；点其他画像先**预览**它选了哪些方向（标注
  "预览中，还没有切换"），确认后才点"更换到该画像"整体切换；支持新建、删除、改名。
- `/api/portraits` 返回增强：`label / default_label / custom / dirs / sel / dir`。

### 3. 顶栏方向按钮显示画像名
- 按钮文字 = 自己起的画像名 > 按方向生成的默认名 > "还没有方向"，
  新建/切换/删除/改名后即时更新。

### 4. 推荐跟着勾选组合走（后端）
- `interests.direction_nodes` 读 `trail.sel`（显式空列表 = 全没勾），
  `user_topics` 按组合内每个方向取前两个话题（总量封顶 6）。
- `reading.daily_for_user` 合并组合内各方向的论文目录，方向名显示为
  `人工智能 + 自然语言处理` 这类组合形式。
- 实测：勾/取消一个方向，今日推荐的论文列表随之变化。

### 5. 添加状态在两处入口可见
- **方向树说明浮层**：已添加的方向标题右侧显示绿色 `✓ 已添加` 标记；
  按钮随状态变为 `添加到我的方向` ↔ `取消添加`，点击后浮层当场刷新；
  "确认这个方向"后浮层不再关闭，直接变为已添加状态。
- **对话页右侧推荐栏**：同样显示 `✓ 已添加` 与 `取消添加`，添加/取消/选方向
  后即时刷新（旧版添加后毫无反馈）；去掉了"· 当前"后缀。

## 二、顶栏与菜单修复

- 方向下拉菜单原用 `right: 120px` 魔法数定位，方向名一长就压到用户按钮上
  （"上方的按钮挤在一起"）。改为挂在方向按钮自己的容器下（`right: 0`）。
- `.app-top` 允许换行并留出间距，方向胶囊宽度收紧，不再互相挤压。

## 三、研读页头部工具栏

**改之前**：标签（工具包/阅读卡/矩阵）、搜索框、搜索、导入 PDF 挤在标题右侧
一行，放不下就横向滚动或挤压。

**改之后**：
- 标题 + 说明（`方向论文目录`）在左，说明位于标题**下方**；
- 所有控件收进下方一个通栏工具栏，**放不下就换行**，无横向滚动条、无卡片底色
  （平铺在页面背景上）；搜索框弹性宽度（可伸展、可收缩）；标签组不许被压。
- 1280/1024/900/760 多档宽度实测无溢出无重叠。

## 四、论文带读页工具栏与滚动联动

**改之前**：论文上方的"选中原文里的一句"栏和"跳到"栏都是
`nowrap + overflow-x`，按钮挤成一条并出横向滚动条；滚动正文时"跳到"无反馈。

**改之后**：
- 两栏合并为一个 `paper-tools` 工具栏（分两行：引文按钮行 + 章节跳转行），
  按钮自动换行、保持正常间距，横向滚动条彻底删除（含窄屏断点）。
- **跳到滚动联动**：读到哪一节，对应章节按钮自动高亮（判定"最后一个滚过视口
  上沿的标题"）；还在顶部作者区时全不亮，滚回顶部清除高亮；点按钮跳转后
  高亮一致；首帧判定等面板挂载完成后再做（避免误亮最后一节）。

## 五、意见反馈功能（新增）

**改之前**：无任何反馈通道。

**改之后**：

### 后端
- 用户库新增 `feedback` 表（`id / user_id / text / status / created_at`，
  建库自动建表；删号时随账号自动清除）。
- 用户接口：`POST /api/feedback`（10–4000 字校验、写入、记事件）、
  `GET /api/feedback?uid=`（只返回本人的）。
- 管理接口（`admin.py`，`X-Admin-Token` 口令保护）：
  `GET /api/admin/feedback`（全量列表，带提交人昵称，新→旧，可按
  `?status=open|reviewed|done` 过滤）、`POST /api/admin/feedback/status`
  （标记处理进度：已收到→已读→已处理）。

### 前端
- **入口**：左侧边栏最底部（"我的 DeepSeek"之下），靠左；"意见反馈"为
  青绿高亮加粗小字带下划线，下面一行小字"项目仍处于开发阶段，我们期待您的宝贵意见"。
  窄屏侧栏横排时只留主文字。
- **反馈页**（标准意见反馈页）：开场为致谢信（"感谢您体验'启研'项目！……"
  三行 + 右对齐署名""启研"项目团队"）；大输入框（10–4000 字、右下角实时字数、
  占位文字"网页bug，使用体验，新功能建议...什么都可以提~"）；提交后提示
  "您的反馈已提交，非常感谢您对'启研'项目的支持！"并清空输入框。
  页面不显示"我提过的"历史卡片（数据照常入库，团队从管理接口看）。
